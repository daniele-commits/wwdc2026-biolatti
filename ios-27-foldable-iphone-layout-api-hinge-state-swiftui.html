iOS 27 prepara le app al pieghevole: nuove API di layout per l'iPhone Fold

Con iOS 27 Apple introduce nel SDK le API adattive per display pieghevoli: SwiftUI e UIKit guadagnano il rilevamento dello stato della cerniera (hinge-state) e la gestione di configurazioni multi-display. L'iPhone pieghevole non è stato annunciato al keynote, ma il framework arriva ora per dare agli sviluppatori il tempo di adattare le loro app prima del lancio hardware di settembre.

Pubblicato: 2026-06-09T04:55:16.258392+02:00 Area tematica: Sviluppatori

Il framework prima del dispositivo

Apple non ha annunciato l'iPhone pieghevole al keynote WWDC 2026 — come atteso, il hardware arriverà con l'evento iPhone di settembre — ma ha introdotto nel SDK di iOS 27 le fondamenta necessarie perché gli sviluppatori adattino le loro app in anticipo. Come documentato da Lushbinary nell'analisi tecnica post-keynote, SwiftUI e UIKit ricevono nuove API di layout adattive: rilevamento dello stato della cerniera (hinge-state detection) e gestione di configurazioni multi-display.

Il principio dichiarato da Apple è che il comportamento atteso sull'iPhone pieghevole sia il reflow fluido del contenuto — non il letterboxing — il che implica un lavoro strutturale per molte app, soprattutto quelle con layout rigidi o con interfacce ottimizzate per proporzioni fisse. Il meccanismo è analogo a quello già visto su iPad con Stage Manager: quando il dispositivo si apre o si chiude, l'app deve ridisporsi in tempo reale.

Un segnale di roadmap

La mossa conferma indirettamente che l'iPhone pieghevole è previsto per settembre 2026. Apple non anticiperebbe la pubblicazione di framework specifici senza avere un calendario hardware definito. Per gli sviluppatori, il messaggio è pratico: chi adotta le nuove API adesso avrà app pronte al day-one del nuovo dispositivo; chi aspetta si troverà a rincorrere.
